# 構成と検証

## 実装構成

React 19 / vinext / Vite / Three.js / Cloudflare Workersを使用する。
実装と静的素材は02.srcに集約し、Viteのvinext({ appDir: '02.src' })とpublicDirで読み込み先を指定する。TypeScriptの@/*も02.src/*を参照する。npm等のツール設定とビルド出力先はルートに維持する。

- app/: 画面（/、/review、/voice-samples）とAPI（/api/cat-chat、/api/cat-voice）。
- components/: UI部品。
- hooks/: Reactフック。
- lib/: 3D表示、移動、音声処理など。
- public/: 3Dモデル、音声、スクリーンショット。

## 秘密情報

00.secretと.env*、.dev.vars*はGit管理外。00.secretは自動で読み込まれない。会話APIの設定はルートの.dev.varsまたは実行環境のSecretで渡す。秘密値をドキュメントや作業記録に記載しない。

## GitSecurityTool

GitSecurityToolはサブモジュール。取得先に同名の内部フォルダがあるため、ルートのpre-commit設定は実際の内部パスを指定する。既存のGLBとスクリーンショットのみ大容量チェックの対象外にし、シークレット検査の対象からは除外しない。

独自のkeywords.yamlを作成・編集する前に、サブモジュールで次の処理を行う。配布版が既に追跡されている場合、info/excludeのみでは追跡が外れない点に注意する。

```powershell
git -C GitSecurityTool rm --cached -- GitSecurityTool/keywords.yaml
```

続けて `git -C GitSecurityTool rev-parse --git-path info/exclude` が返すファイルに `/GitSecurityTool/keywords.yaml` を追記する。この変更はローカル専用とし、サブモジュールのコミットは作成しない。元の配布版keywords.yamlは今回変更していない。

## 検証項目

- npm run build: 移動後の画面・APIをビルドできること。
- npm run dev: /、/review、/voice-samplesおよび静的素材が取得できること。
- npm run lint: 既存の指摘を含むコード検査。
- Python環境の準備後: py -m pre_commit installと全ファイルのチェック。
- 手動: 3D表示、なでる・おもちゃ・ごはん、マイク会話、音声再生。
