01 文書概要

本書は、既存ソースコードから画面、処理、インターフェース、状態管理、例外処理を整理した実装準拠の詳細設計書である。主対象は標準のおさんぽ版。比較用モデルと診断機能も対象に含む。

アカウント登録、アプリ独自の認証、DB、セーブ・端末間同期は実装されていない。3Dの触れ合いは会話用APIキーなしで利用できる。会話には外部通信とサーバー側のキー設定が必要。

外部サービスの仕様・稼働状況は調査対象外。モデル名、上限値、待機時間はコード内の設定値を示す。検証結果は既存の作業記録と今回の文書検査を区別して記載する。

05 3D・猫の行動制御

初期化と描画

標準版はGLB読込後にシーン、レンダラー、カメラ、照明、家具、ラグ、器、おもちゃを生成する。必須ノードHeadRoot、Neck、TailRoot、Walking_Torso、EyeL、EyeRを検査し、不在なら例外とする。毛並みはCanvasTextureとInstancedMeshの毛束で補う。

項目標準版設定
レンダラーantialias=true、alpha=false、pixelRatio上限2、PCFSoftShadowMap、sRGB、ACESFilmic、露出1.15。
カメラPerspectiveCamera：FOV 36、near 0.1、far 70。初期座標(4.2, 3.1, 7.9)。
視点制限距離4.2〜12、極角0.45〜π×0.48、パン無効、減衰あり。
画面サイズResizeObserverでホスト寸法を監視し、カメラaspectとrendererサイズを更新。

行動状態

CatStateはidle / walk / sit / groom / sleep / stretch / look / approach / dash。候補はプレイヤー近接や眠気で変化し、直前の状態が続かないよう最大3回選び直す。プレイヤー距離判定は1秒間隔、5以下で近接とみなす。

状態主な動作・終了
idle / walk / dash待機／経路移動／速度倍率2.35の短距離移動。walk・dashは到着時idleへ。
sit / groom座り5〜15秒／毛づくろい3.8〜5.6秒。移動停止。
sleep / stretch睡眠15〜40秒。終了時に眠気を0へ戻し、3秒の伸びへ遷移。
look / approach2〜4秒見つめる／カメラ位置から算出したプレイヤー近傍へ移動。接近到着後に鳴き、sitまたはidle。

触れ合いと給餌

なでる命中時は移動を3秒停止し、なでられポーズを1.4秒継続、affectionを2加算する。おもちゃは猫から2未満の目標位置で反応し、funを1加算。両者のrewardは共通の0.3秒間隔制限を持ち、上限100に丸める。

給餌はfullnessが98以上なら拒否する。器への経路を要求し、給餌位置から0.12未満・経路消化済み・向きの差0.03未満になった時点で食事開始。fullnessを18、affectionを3加算し、4秒後に食事終了。食後3秒待機し、鳴き声を再生する。

睡眠等のポーズは胴体・頭の位置やスケール、四肢の目標を滑らかに補間して表現する。通常の鳴き声は6〜12秒間隔で試行し、睡眠中は抑制する。

06 移動・歩行設計

定義内容
座標Point={x:number,z:number}。床面はXZ、上下はY。
ROOMx：-3.45〜3.45、z：-2.45〜2.65。
器 / 給餌地点BOWL=(1.3,1.45)、FEED_SPOT=(1.3,0.11)。
移動不可非有限値、部屋外、x>0.5かつx<4.8かつz<-0.98、器からの距離1.26以下。
線分検査clearSegmentは最大約0.08刻みで始点から終点までisFreeを検査。
経路探索直接到達可能なら終点のみ返す。それ以外は0.24間隔グリッド、8近傍A*、ユークリッド距離のヒューリスティック。対角線も線分検査する。
経路簡略化始終点を接続可能な最寄りグリッドへ対応付け。復元した経路から、直接見通せる最も遠い点を順次選択。
失敗始終点不正、接続点なし、経路なしで空配列。requestはfalse。

WanderControllerはdtを0〜0.05に制限。最大旋回量はdt×1.7、向きの差が0.38を超える間は目標速度0。通常速度は最大0.55×倍率で指数補間する。目標距離0.075未満で次の経路点へ進み、最終到着後は3〜7秒待機する。移動衝突時は経路を破棄し0.5秒待機する。

四肢の歩行

CatGaitはFL→HR→FR→HLの順に位相を0.25ずつずらす。Upper/Lower/Footの各関節を必須とし、二節のIKで足を接地点へ向ける。遊脚時間0.27秒、持ち上げ量はsin(πp)×0.11。到達距離を脚長内へ制限し、停止中も接地点のずれが大きい場合に踏み直す。床高さgroundHeightを反映し、ラグ付近の高さを補間する。

07 音声会話設計

idle / error→ 話す →recording→ 停止 / 12秒 →transcribing→thinking→speaking→idle
  1. getUserMedia({audio:true})でマイクを取得し、AudioContextをresumeする。
  2. ScriptProcessorNode(4096,1,1)で第0チャンネルをFloat32Arrayとして蓄積。Gain=0で出力に接続し、入力のモニター再生を防ぐ。
  3. 手動停止または12秒のタイマーでチャンクを連結。マイクのtrack、ノード、AudioContext、タイマーを解放する。
  4. 収録が0.25秒未満ならエラー。RMSが0.001未満なら診断上エラーを表示するが、それだけでは推論を中止しない。
  5. sampleRate / 16000の比率で最近傍サンプルを抽出し、16kHz mono PCMを生成する。
  6. 初回のみTransformers.jsを動的importし、Whisper tiny q8を初期化。language=japanese、task=transcribeで推論する。現在はHomeから直接実行し、専用Workerには分離しない。
  7. 空の認識結果はidleへ戻して案内表示。非空の場合は/api/cat-chatへ認識文と履歴を送信する。
  8. 返答を表示し、TTSQuestにtextとspeaker=8を指定して合成依頼。750msごと、最大40回の状態確認で音声準備を待つ。
  9. MP3をAudioで再生。合成取得・待機・再生失敗時はSpeechSynthesisへフォールバックする。

標準読み上げはja-JP、rate=1.04、pitch=1.18。利用可能なら名前にsayakaを含む日本語音声を選ぶ。読み上げ完了でidle、標準音声も失敗すればerrorへ移る。

非同期処理と診断

recognitionGenerationを開始ごとに増やし、各await後や音声完了時に現行世代と比較する。古い処理は画面更新を抑止する。アンマウント時も世代を進める。これは通信・推論の実行自体をキャンセルする仕組みではない。

DebugStepはname/status/detailを保持し、マイク取得、PCM収録・変換、モデル準備、推論、認識結果を記録する。現行JSXにはこのdebug配列を一覧表示する領域はない。コンソールには世代・入力種別・認識結果などを出力する。

固定PCM入力は猫の鳴き声であり、日本語認識の正確性を保証する試験ではない。文字列が返れば通常の会話API・読み上げへ進む。

08 API仕様

両APIはPOSTのJSONを受け付け、JSON応答にCache-Control: no-storeを付ける。キーはcloudflare:workersのenvから読み込む。キーが文字列でない、または10文字未満なら、本文解析より先に503を返す。

API-01 POST /api/cat-chat（通常経路）

{
  "message": "こんにちは",
  "history": [
    { "role": "user", "content": "前の発言" },
    { "role": "assistant", "content": "前の返答" }
  ]
}

成功 200: { "reply": "こんにちは。いっしょに遊ぼう。" }
失敗:     { "error": "画面に表示する案内文" }
項目実装仕様
message文字列をtrim後、1〜600文字。空・型不正・長すぎは400。
history省略・配列以外なら空。末尾6要素を先に抽出し、roleがuser/assistant、contentが600文字以下の文字列の要素のみ採用。空文字は許容。
OpenRouterPOST https://openrouter.ai/api/v1/chat/completions。Authorization: Bearerキー、Content-Type: application/json。
生成指定model=inclusionai/ling-3.0-flash-vl:free。system→履歴→現在発言の順。systemで猫「むぎ」、やさしい日本語、2文まで等を指示。max_tokens・temperatureの明示指定なし。
待機・再試行各fetchのタイムアウト60秒。HTTP成功かつcontentが空・非文字列の場合だけ1回再試行。HTTP失敗・例外は再試行しない。
返答最初のchoiceのmessage.contentをtrimし、最大900文字へ切り詰める。
ログ試行回数、HTTP状態、model、choices件数、finish_reason、content型・長さ、error有無、usage。例外は種類とメッセージ。

API-02 POST /api/cat-voice（現行画面では未使用）

要求: { "audio": "Base64形式のWebMデータ", "history": [] }
成功: { "reply": "返答文", "transcript": "文字起こし文" }
項目実装仕様
audio必須文字列、1〜3,000,000文字。Base64デコードや実際の形式検証は実装していない。historyの整形はAPI-01と同様。
文字起こしOpenRouter、nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free、input_audio形式webm、max_tokens=180、temperature=0、タイムアウト30秒。
会話生成文字起こし成功後にOpenRouter、openrouter/free、max_tokens=140、temperature=0.8、タイムアウト20秒。再試行なし。
応答整形replyは900文字、transcriptは600文字まで。空または「聞き取れませんでした」の認識結果は502。

エラー応答

HTTP条件
400JSON解析失敗、message/audioの必須・文字数検査違反。

10 例外処理・リソース管理

場面処理
3Dモデル読込失敗Homeでerrorを設定し、再読み込みやChrome/Edgeの利用を案内。
マイク取得・準備失敗診断を記録し、releaseMic、error状態、権限の再確認案内。
モデル取得・推論失敗該当診断をerrorにし、接続確認・再読み込みの案内。

TTSQuest失敗SpeechSynthesisへフォールバック。そちらも失敗すればerror。
猫の鳴き声失敗例外を吸収しデコード用Promiseをリセット。後の再生で再取得可能。

鳴き声はAudioContextを遅延生成し、ユーザー操作でunlockする。音量0.55、pending/activeで重複再生を抑制し、通常は再生開始から3秒未満の再試行を抑制する。食後再生はこの3秒制限を除外するが、消音・重複制御は維持する。

マイク取得直後から参照への登録までの間に中断・例外が発生する経路は、ローカル変数側のtrack解放を追加確認する必要がある。外部APIの認証、レート制限、同時実行抑制、総リクエストサイズ制限も現行実装では確認できない。
