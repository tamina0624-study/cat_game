01　目的・対象範囲

ブラウザ上の小さな3Dの部屋で、猫「むぎ」をなでる、おもちゃで遊ぶ、ごはんをあげる体験を提供する。日本語の音声会話と、開発・表現確認用のモデルレビューおよび音声試聴を備える。

項目設計内容
対象利用者猫との触れ合いを楽しむ利用者、3Dモデルや音声表現を確認する開発者
対象機能3D表示、触れ合い、状態表示、視点操作、モデル保存、音声会話、モデル比較、音声試聴、音声認識診断
対象外アカウント登録、ユーザー認証、セーブ、端末間同期、DBによる永続化
記述の基準作成時点のリポジトリ内のコード・資料。外部サービスの提供状況や本番動作を保証する資料ではない。

本書は現行実装の基本設計を整理したもの。性能目標、運用体制、将来機能など未決定の内容は、確認事項として明記する。

02　システム構成

ブラウザ

会話API↔OpenRouter
返答生成

返答文はブラウザへ返却し、ブラウザからTTSQuestへ送信してVOICEVOX音声を取得・再生する。音声取得や再生が失敗した場合は、ブラウザ標準の読み上げを試みる。GLBモデルと鳴き声は静的アセットとして配信する。

配信・APIvinext 1.0.0-beta.5、Vite 8、Cloudflare Workers。ページとサーバーAPIを提供。
外部連携OpenRouter：会話生成。TTSQuest / VOICEVOX：音声合成。Web Speech API：代替読み上げ・音声試聴。

04　機能設計

ID機能基本動作
F-013D初期化クエリのモデル指定に応じた実装を起動。通常はキジ白モデルを読み込み、部屋と猫を描画。失敗時は再読込や対応ブラウザの案内を表示。
F-02触れ合いなでる：猫をドラッグ。おもちゃ：マウスでじゃらす。ごはん：クリックで与える。キー1・2・3でもモード変更。
F-03猫の状態・行動触れ合いに応じて状態値とメッセージを更新。通常版は歩行・座る・毛づくろい・睡眠等の自律行動を持つ。
F-04視点・モデル操作右ドラッグで見回す、ボタンで視点を戻す。猫モデルのダウンロードを提供。
F-05鳴き声Web Audio APIで鳴き声を再生。連続再生を抑制。消音ボタンは鳴き声を制御し、会話音声には連動しない。
F-06音声会話録音→文字起こし→返答生成→音声合成→再生。処理中は追加録音を抑制。
F-07認識診断固定音源 /audio/meow.ogg をPCMへ変換してWhisperへ渡す。認識文が空でなければ会話APIへ進むため、外部通信を伴う場合がある。

画面を離れる際は3Dリソースの破棄、録音ストリームの停止、会話音声と読み上げの停止を行う。

05　音声会話の処理設計

  1. 利用者が「話す」を押すとマイク権限を要求し、音声をモノラルPCMとして収録する。
  2. 「止める」または12秒経過で録音を停止。短すぎる録音はエラー案内を表示する。
  3. 16kHzへ変換したPCMをブラウザ内のWhisperへ渡し、日本語の文字起こしを実行する。初回は認識モデルの取得が必要。
  4. 認識文と直近の会話履歴を POST /api/cat-chat へ送信する。
  5. サーバーがOpenRouterへ問い合わせ、猫「むぎ」としてやさしい日本語・二文までの返答を指示する。
  6. 返答を画面へ表示し、TTSQuestによるVOICEVOX（春日部つむぎ、speaker 8）音声を取得・再生する。失敗時は標準読み上げを試みる。
idle → recording → transcribing → thinking → speaking → idle
             └──────── 各処理の失敗 → error → 再操作
録音中の再押下：録音停止 ／ 認識・生成・再生中：録音操作を抑制

実行ごとの世代番号を照合し、古い非同期結果による画面更新を防ぐ。認識はメイン画面からTransformers.jsを直接利用しており、専用Workerへの分離は現行の通常経路に適用されていない。

06　API設計

API-01：POST /api/cat-chat

項目仕様
要求JSON。message：前後の空白除去後1〜600文字。history：任意配列。末尾6件からroleがuser / assistantでcontentが600文字以内の要素を採用。
成功HTTP 200、{ "reply": "返答文" }。空白を除去し、最大900文字を返却。
外部要求OpenRouter chat/completions。コード指定モデルは inclusionai/ling-3.0-flash-vl:free。要求ごとのタイムアウト60秒。正常応答の返答文が空の場合のみ1回再試行。
失敗400：JSON不正・入力不正。503：APIキー未設定または形式条件不適合。502：外部API異常・空応答・通信失敗。
キャッシュ成功・失敗とも Cache-Control: no-store。
{
  "message": "むぎ、こんにちは",
  "history": [{ "role": "assistant", "content": "いっしょに遊ぼう。" }]
}

API-02：POST /api/cat-voice（通常画面から未使用）

Base64のWebM音声を受け取り、OpenRouterで文字起こしと会話生成を行う別経路。通常のマイク会話では使用しない。

項目仕様
要求audio：空でない文字列、最大3,000,000文字。history：会話APIと同様に直近6件から検証して採用。
成功HTTP 200、{ "reply": "返答文", "transcript": "認識文" }。返答最大900文字、認識文最大600文字。
外部処理文字起こしは nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free（30秒）、会話は openrouter/free（20秒）。いずれもコード上の指定。
失敗400：入力不正。503：APIキー設定不備。502：認識失敗・会話生成失敗・通信失敗。

エラー応答の共通形式は { "error": "利用者向けメッセージ" }。モデル名の :free はコードの指定であり、料金・利用可能性を保証しない。

07　データ・状態管理

DB、テーブル、マイグレーションはないため、ER図は対象外。状態はブラウザのメモリに保持し、再読み込み後には復元しない。

データ内容・保持先ライフサイクル
猫の状態affection / fullness / fun。通常版の初期値は42 / 55 / 50。画面は百分率表示。ゲーム実行中
操作・会話状態選択モード、準備完了、消音、メッセージ、録音・認識・再生状態。Reactのstate / refで管理。画面表示中
会話履歴user / assistantと本文。APIへ渡す履歴は直近6件。画面表示中
音声データ一時PCM、認識文、合成音声。通常経路で録音PCMを会話APIへ送信しない。処理用に一時保持。アプリによる永続保存はない。
静的素材GLBモデル、鳴き声、画面キャプチャ。02.src/public/で管理
秘密情報OPENROUTER_API_KEY。Workersの環境バインディングで参照。サーバー側の設定で管理

08　非機能・セキュリティ

観点現行設計・制約
動作環境WebGLと音声APIが利用可能なブラウザ。Chrome / Edgeを想定。マイク利用にはHTTPSまたはlocalhost等のセキュアな実行環境と権限が必要。
性能3D描画と音声認識は端末性能に依存。初回モデル取得に時間を要する。FPS・応答時間・同時利用者数の数値目標は未定義。
可用性触れ合いはOpenRouterのキーなしで利用可能。会話・外部音声合成は外部サービスの状態に依存。全面的なオフライン動作は保証しない。
秘密情報管理APIキーはブラウザへ渡さない。ローカル設定はルートの.dev.vars等を利用し、Git対象外とする。00.secretは自動読込されない。
入力・通信会話APIで型・文字数・roleを検証。認識文・履歴はOpenRouter、返答文はTTSQuestへ送信。別音声APIを直接使う場合は録音もOpenRouterへ送信。
公開APIの運用確認したAPIコードには利用者認証・レート制限がない。公開範囲や費用上限に応じてアクセス制御を検討する。
操作支援主要ボタンのラベル・選択状態、メッセージのstatus属性、キー操作を実装。画面全体のアクセシビリティ検証は未完了。
ログAPIは外部応答の要約・通信エラーを出力。音声診断ログには認識文が含まれるため、共有前に内容を確認する。
